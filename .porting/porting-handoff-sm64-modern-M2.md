# Handoff: M2 AppKit Host

## What Was Done

Implemented a parallel Swift 6.4/macOS 27 AppKit application generated by XcodeGen. The hardened Apple Development-signed bundle owns a programmatic 4:3 window and pixel-sized `CAMetalLayer`, exposes native menus/fullscreen, resolves local development game/save paths, and drives the existing versioned C lifecycle from one dedicated owner thread at the legacy 30 Hz cadence. A native-core Make flavor excludes the legacy entry/platform adapter and inactive API backend members while preserving the original portable targets. `script/build_and_run.sh` is the single build, signing, run, LLDB, logging, telemetry, and PID-scoped verification entrypoint, with a matching Codex Run action.

## Ground Truth Comparison

M2 is a non-rendering foundation milestone and intentionally creates no `MTLDevice`, drawable, render pass, or GPU command. The discovery report contains no checked-in reference captures or traces, so no GPU/RenderDoc comparison was applicable. The ignored local screenshot `build/sm64-modern-m2-validation.png` was inspected: it shows the expected native 4:3 black layer-backed window with standard traffic-light controls. Black content is expected until M3 implements clear and present.

## What's Deferred

- `grep -R "STUB(M3)" SM64Modern` — create the Metal 4 device/presentation loop and publish rendering capability only after that path is complete.
- `grep -R "STUB(M5)" SM64Modern` — install native keyboard/mouse/controller routing and AVAudioEngine callbacks before publishing audio capability.
- `grep -R "STUB(M8)" SM64Modern` — replace the legacy 30 Hz host cadence with the audited deterministic 1/60-second full-world clock.
- `grep -R "STUB(M6)" include src` — inherited M1 gameplay snapshot/effect schemas remain deferred to deterministic gameplay parity work.

## Known Issues

- No matching `io.github.deestiz.sm64modern` provisioning profile currently grants `com.apple.developer.sustained-execution`. Local Debug omits it; the provisioned Release entitlement file retains it.
- No Developer ID Application identity is installed, so direct distribution signing/notarization remains unavailable.
- The Xcode target builds unsigned by design (`CODE_SIGNING_ALLOWED=NO`); the canonical script signs nested debug code and the app with the local Apple Development identity.
- There are no checked-in GPU/reference artifacts yet. M3 must establish the first Metal capture baseline.

## Watch For

- Keep using `script/build_and_run.sh`; a bare `xcodebuild` product is unsigned and is not equivalent runtime evidence.
- Preserve `GameView.makeBackingLayer()` and backing-pixel `drawableSize` updates. Do not replace the view with `MTKView`.
- Preserve `viewDidAppear`'s one-shot guard and engine-start-last ordering when inserting M3 device/display-link setup.
- Do not set `SM64_MODERN_PLATFORM_CAP_RENDERING` until device, drawable, clear, present, error handling, and owner-thread integration are all valid.
- The native archive intentionally excludes SDL/OpenGL/D3D backend translation units; do not reintroduce them to satisfy new Metal symbols.
- M3 touches rendering, so GPU capture/analysis and Metal validation are mandatory during validation.

## Key Decisions Made

- Use direct AppKit rather than SwiftUI, `NSApplicationMain`, or `MTKView`; AppKit owns the window and raw `CAMetalLayer` while the C core owns gameplay state.
- Swift receives only the public POD/function-table ABI from `include/sm64_modern.h`; no legacy game object graph crosses the concurrency boundary.
- AppKit starts only after the window/layer has a nonzero backing-pixel size, and termination blocks until owner-thread core shutdown completes.
- M2 keeps platform capabilities at zero. Rendering begins in M3, input/audio in M5, and fixed 60 Hz simulation in M8.
- ROM-derived data remains local and unbundled; Debug development paths resolve through environment overrides or expanded Info.plist values.
- Local Debug uses hardened Apple Development manual signing without mutating developer-portal state.
